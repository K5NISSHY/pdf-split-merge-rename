# PDF 分割・結合・ファイル名自動生成ツール（統合版）

PDFを1ページずつに分割し、Excelのセル値でファイル名を付ける Windows 11 向けツールです。
これまで別リポジトリで作った2本（**PDF-Split-Rename** と **PDF-Split-Rename-By-Cell**）を
1ウィンドウに統合したもので、共通の入力欄の上でタブ切り替えにより2つの命名モードを使い分けられます。
v2.0.0 では同じウィンドウに **「PDF結合」** と **「Excelでリネーム」** の2タブを加え、
分割 → 結合 → リネームまでを1本のツールで扱えます。

- **バージョン:** 2.0.2
- **製作者:** K5NISSHY
- **継承:** `refs/PDF-Split-Rename/` と `refs/PDF-Split-Rename-By-Cell/` に、元となった2ツールの参考コードの写しを読み取り用同梱しています。本ツールのUI・事前検査・書き出しの安全規則・日本語エラー文言は、この2本の挙動を踏襲しています（分割タブ2枚の挙動とエラー文言は v1.0.0 から変更していません）。

## フォルダー構成

- `pdf_split_merge_rename.py`: GUI・エントリポイント（共通欄＋タブ4枚＋プレビュー一覧欄）
- `split_core.py`: 共通コア（Excel読み取り・ファイル名検証・PDF読み込み・一時書き出し/ロールバック・既存チェック）
- `natural_sort.py`: 自然順（`001 → 003 → 008 → 9 → 10`）の並び替えキー
- `merge_core.py`: PDF結合（対象列挙・名前検査・結合プラン・一時書き出し/ロールバック）
- `rename_core.py`: Excelでリネーム（対象列挙・プラン・衝突検査・2段階リネーム/ロールバック）
- `modes.py`: 出力ファイル名生成（分割2モードとリネーム2ルール）
- `preview.py`: プレビュー行の生成（`[既存]` / `[重複]` / `[読込不可]` / `[衝突]` / `[変更不要]` 判定。書き出し・名前変更は行わない）
- `pathops.py`: 保存先がネットワークドライブ（NAS共有）でも同じ操作ができるための共通補助（一時名の代替・名前変更の再試行・コピー代替・エラー案内）
- `test_pdf_split_merge_rename.py`: 単体テスト（`py -3 -m unittest -v` で実行）
- `tools/verify_independent.py`: 実データを作る独立検証スクリプト（分割・結合・リネームを機械判定）
- `tools/verify_assistant.py`: 実装とは別系統の検証（アシスタント設計。FR-1〜FR-16 / FR-C / FR-M / FR-R を実データと非表示GUIで機械判定）
- `tools/verify_gui_display.py`: GUIを実ウィンドウとして一瞬表示し、タブ4枚の描画を確認してから閉じるスモーク
- `tools/make_samples.py`: 検証用サンプル資料（本文に文字があるPDF・Excel・結合入力・リネーム入力）を作るスクリプト
- `tools/run_sample_split.py`: サンプル資料で両モードの分割を実実行し、`samples\検証結果` に保存して機械判定するスクリプト
- `tools/run_sample_merge_rename.py`: サンプル資料で結合とリネームを実実行し、`samples\検証結果` に保存して機械判定するスクリプト
- `tools/verify_release_check.py`: リリース前の独立検査（自然順の境界・結合順序・既存非上書き・暗号化/破損・リネームの衝突中止とロールバック・GUIの自動補完を別観点で機械判定）
- `tools/make_dist.py`: 配布用の最小パッケージ（受け取り用フォルダーと zip）を作るスクリプト
- `samples/`: 検証用資料（`sample_5pages.pdf` / `sample_names.xlsx` / `結合入力` / `リネーム入力`）と実行結果（`検証結果\連番`・`検証結果\セル別`・`検証結果\結合`・`検証結果\リネーム`）
- `起動.bat`: ダブルクリックで起動
- `docs/`: 要件定義・実装依頼などのプロジェクト文書
- `refs/`: 参考コードの写し（読み取り専用。変更・削除しないこと）

## 必要なもの

- Windows 11
- Python 3.10 以降
- Excel ブック（`.xlsx` または `.xlsm`）

`起動.bat` は `py -3`、利用できない場合は `python` で Python を探します。Python が見つからない場合は、[Python公式ダウンロードページ](https://www.python.org/downloads/windows/)から Python 3.10 以降をインストールし、「Add python.exe to PATH」を有効にして起動し直してください。起動時に `pypdf` と `openpyxl` が利用できるか確認し、不足していれば `pip install --user pypdf openpyxl` で自動インストールします（初回はインターネット接続が必要）。

- `pypdf`: PDFの読み込みと1ページごとの書き出し
- `openpyxl`: `.xlsx` / `.xlsm` ブックからセル値を読み込み
- `tkinter`: 画面表示（Pythonに付属する標準ライブラリ）

## 使い方

1. `起動.bat` をダブルクリックします。
2. 上部の共通欄で「分割するPDF」「Excelファイル」を選びます。Excel選択後はシート欄にシート名が一覧表示され、アクティブシートが初期選択されます。PDFを選ぶと出力先フォルダーにPDFと同じフォルダーが初期値として入ります。
3. 下部のタブで処理を選びます（タブを切り替えても各欄の入力はそのまま残ります。実行ボタンは各タブの中にあり、他タブのボタンを誤って押すことはありません）。
   - **セル値＋連番**: セル番地（例: `A1`）1つの値をベース名にし、`{ベース名}_{ページ番号:03d}.pdf` で出力します（連番は先頭が `001`、1000ページ超では桁が伸びます）。
   - **セル別（連番なし）**: 開始セルから同じ列を下方向へPDFのページ数分読み、`{セル値}.pdf` で出力します。
   - **PDF結合**: 入力フォルダーの直下にあるPDFを自然順（`001 → 003 → 008 → 9 → 10`）で1つに結合します。「結合後のファイル名」の初期値は自然順で最初のPDF名で、書き換えればその名前が使われます（`.pdf` は補います）。出力先が空なら入力フォルダーが使われますが、その場合は初期名が入力PDFと同名になるため、別の名前を入れてください（別フォルダーに出力するなら初期名で構いません）。
   - **Excelでリネーム**: 入力フォルダーの直下のPDFを自然順に並べ、Excelの命名ルールで名前を変えます。ルールは **「固定セル値＋連番」**（`{A1の値}_{001..N}.pdf`）と **「開始セルから下の行のセル値」**（開始セルから同列をN個）の2つで、セル番地を添えます。
4. 必要なら「プレビュー」を押します。タブに応じた一覧（分割: `ページ番号/出力ファイル名/状態`、結合: `順序/入力PDF/ページ数/状態`、リネーム: `順序/現在のファイル名/新しいファイル名/状態`）が表示され、`[既存]` / `[重複]` / `[読込不可]` / `[衝突]` / `[変更不要]` が付きます。プレビューでファイルが書き出されたり、名前が変わったりすることはありません。
5. 各タブの「分割を実行」「結合を実行」「リネームを実行」を押します。実行は常にその時点の入力で再計算して行われます。

## 出力例

セルの値が `ABC123`、PDFが3ページで「セル値＋連番」の場合:

```text

ABC123_002.pdf
ABC123_003.pdf
```

A1・A2・A3 に `あいう`・`かきく`・`さしす` があり「セル別（連番なし）」の場合:

```text
あいう.pdf
かきく.pdf
さしす.pdf
```

```text
報告書.pdf   （001 → 003 → 008 → 9 → 10 の順に全ページを連結）
```

```text

003.pdf → 報告書_002.pdf
008.pdf → 報告書_003.pdf
9.pdf   → 報告書_004.pdf
10.pdf  → 報告書_005.pdf
```

## 事前検査と安全性

- 実行前に全件を検査し、1件でも不正があれば処理を開始しません: 空欄セル / ファイル名に使えない文字（\\ / : * ? " < > |・制御文字）/ 末尾の空白・ピリオド / Windows予約名（CON, PRN, AUX, NUL, COM1-9, LPT1-9）/ 大文字小文字を区別しない重複名（セル別モード）。
- 出力予定ファイルが1つでも既に存在する場合、上書きせず処理を中止します（既存ファイル名を最大8件＋「ほか N 件」で表示）。
- 全ページを出力先内の一時フォルダー（`~pdf_split_*`。保存先が `~` 始まりの名前を拒否する共有の場合は `.pdf_split_*`）へ書き出してから移動します。失敗した場合は作成済みの出力を削除して後片付けします。
- 結合は全PDFを先に読み込んで検査し、1つでも読めないものがある場合はエラー一覧（先頭8件＋「ほか N 件」）を出して開始しません。結合結果は `.pdf_merge_*`（共有では `~pdf_merge_*`）経由で作成し、同名の出力先が既にあれば中止します（上書きなし）。入力PDFと同じ名前を出力名にはできません。
- 結合後ファイル名の初期値は自然順で最初のPDF名ですが、**出力先を入力フォルダーと同じにした場合はその名前が既に使われているためそのままでは実行できません**（「入力PDFを出力名にできません」と案内します）。同じフォルダーに出力する場合は別の名前（例: `報告書`）を入れてください。出力先を別フォルダーにすれば初期値のまま使えます。
- 結合ではしおり（ブックマーク）と文書情報は引き継がれず、ページのみを連結します。
- リネームは実行前に新しい名前同士の重複と既存ファイルとの衝突を検査し、1件でも衝突すれば1つも名前を変えません。**名前を変えないファイル（現在名と新名が同じもの）の名前を別のファイルが使う場合も衝突として中止します**（そのファイルは動かさないため、放置すると上書きになる）。実行は「現在名 → 一時名（`~pdf_rename_tmp_*`。`~` 始まりを拒否する共有では `.pdf_rename_tmp_*`） → 新しい名前」の2段階で行い、途中で失敗した場合は変更済みの名前をすべて元へ戻します。名前が同じファイルは `[変更不要]` としてスキップするため、同じ条件を再実行できます。
- リネームのあとは、新しい名前のファイルがすべて揃っているかを確認します。揃っていなければ「名前を変更したはずのファイルが入力フォルダーに見当たりません」とエラーで報告します（成功として黙って終わることはありません）。
- 元のPDF・Excelブックは読み取りのみで変更しません（リネームで変わるのは名前だけで、中身のハッシュは変わりません）。
- 空のパスワードで開けない暗号化PDF、壊れたPDF、読み込めないExcelはエラーで中止します。
- セル番地・開始セルは `A1`、`B3` などで指定します（`$A$1` 形式も可）。

## リネームタブは「入力フォルダー」内で名前を変えます

リネームタブは**入力フォルダーに指定したフォルダーの中だけで**ファイル名を変えます。コピーを作らず、共通欄の「出力先フォルダー」はこのタブでは使いません（分割・結合タブだけが使います）。完了時に表示される「フォルダー: ...」が、名前が変わったファイルのある場所です。

- 名前が変わったはずのファイルが見当たらないときは、そのフォルダーで表示を更新（F5）し、`~pdf_rename_tmp_` や `.pdf_rename_tmp_` で始まるファイルがないか確認してください。あれば、そのまま残さずエラー文言といっしょに報告してください。
- 別のフォルダーへ名前を変えたコピーを置きたい場合は、まずコピーをそのフォルダーへ置いてから、そのフォルダーを入力フォルダーにしてリネームしてください。

## ネットワークドライブ（NAS共有）での利用

入力PDF・Excelブック・出力先には、ネットワーク上の共有フォルダー（`\\192.168.1.50\PDF\...` のような UNC パス、または割り当て済みのネットワークドライブ）をそのまま指定できます。分割・結合・Excelでリネーム・プレビューの4機能とも、共有フォルダーからの読み込みと共有フォルダーへの保存で動作します。

共有フォルダーはローカルフォルダーと同じに扱えないことがあるため、実行のたびに次を自動で行います。

- 一時フォルダーと一時の名前は `~` 始まり（`~pdf_split_*` / `~pdf_merge_*` / `~pdf_rename_tmp_*`）で作ります。`.` 始まりは一部の共有（Samba の既定設定など）でエクスプローラーから隠れたり拒否されたりするため、途中で止まったときにPDFが消えたと誤解されないよう `~` を先に使います。`~` 始まりを拒否する共有では `.` 始まりへ切り替えます。
- 書き出したPDFは内容までサーバーへ届けてから閉じ（`fsync`）、その後に名前を動かします。
- 名前を動かす操作が共有の一時的な混雑（Windowsエラー 32 / 33 / 64）で失敗した場合は、少し待って計5回までやり直し、それでも動かなければ「コピー → 元ファイル削除」で同じ結果にします。既存ファイルの上書きは行いません。
- 一時フォルダー・一時ファイルの削除も少し待ってやり直し、残骸を残しません。
- 失敗したときは原因の案内を添えます（「アクセスが拒否されました。共有フォルダーが読み取り専用になっていないか、アクセス権を確認してください」/「保存先はネットワーク上の共有フォルダーです。共有が一時的に混雑している可能性があります」）。

共有先で保存できないときは、次を確認してください。

- 共有が**読み取り専用**で開かれていないか（書き込める共有・フォルダーを選ぶ）
- 出力先に**同じ名前のファイルが既にないか**（このツールは上書きせず中止します）
- 結合で**入力フォルダーと出力先が同じ**とき、既定の出力名が入力PDFの名前と衝突していないか
- 処理後に `~pdf_split_*` などの残骸だけが残っていないか（残っていればエラー文言をそのまま教えてください）

実際の共有フォルダーを使う確認テストも同梱しています。環境変数 `PDFSMS_TEST_SHARE` に共有パスを設定すると実行され、未設定時は 4件スキップになります。

```text
set PDFSMS_TEST_SHARE=\\192.168.1.50\PDF共有
py -3 -m unittest -v test_pdf_split_merge_rename.NetworkShareTests
```

## Excelの数式セル

数式セルでは数式自体を計算せず、Excelブックに保存された計算結果をファイル名に使います。計算結果が保存されていない、空、またはエラー値（`#REF!` など）の場合は処理を中止し、Excelでブックを開いて再計算・保存してから再実行するようお知らせします。

## プレビュー後の入力変更

プレビュー後にPDF・Excel・シート・セル・出力先のいずれかを変更すると、一覧は消えて「入力変更あり: プレビューを更新してください」と表示されます。古い一覧を見続けたまま実行することはなく、「分割を実行」は常に現在の入力で組み直します。一覧はデータとして全件保持し、表示は12行程度の欄でスクロールでき、100件超は末尾に「ほか N 件」行をまとめます。

## テストと検証

テストはプロジェクトフォルダーで次を実行します。

```text
py -3 -m unittest -v
```

実PDF・実Excelを一時フォルダーに作る独立検証は次を実行します（全件成功時に `TOTAL: <成功>/<総数>` と表示され、終了コード0）。

```text
py -3 tools\verify_independent.py
```

要件項目を別系統で洗い直した検証（アシスタント側）と、GUIの実表示スモーク、サンプル資料での実実行も同じ形式で合否を出力します。

```text
py -3 tools\verify_assistant.py
py -3 tools\verify_gui_display.py
py -3 tools\run_sample_split.py
py -3 tools\run_sample_merge_rename.py
py -3 tools\verify_release_check.py
py -3 tools\make_samples.py
```

v2.0.2 での実測値（Windows 11 / Python 3.15.2・pypdf 7.1.1・openpyxl 3.1.5）: `py -3 -m unittest -v` が `Ran 130 tests` / `OK (skipped=4)`（`PDFSMS_TEST_SHARE` を設定して実行すると共有フォルダーでの 4機能確認が走り `OK`）、`tools\verify_independent.py` が `TOTAL: 45/45`、`tools\verify_assistant.py` が `TOTAL: 65/65`、`tools\verify_gui_display.py` が `TOTAL: 1/1`（実ウィンドウ・タブ4枚）、`tools\run_sample_split.py` が `TOTAL: 13/13`、`tools\run_sample_merge_rename.py` が `TOTAL: 23/23`、`tools\verify_release_check.py` が `TOTAL: 48/48`。詳細は `docs/PROJECT_DOCUMENT.md` 第6章。

| `pdf_split_merge_rename.py` | 必須（起動の入口・タブ4枚のGUI） |
| `split_core.py` / `natural_sort.py` / `merge_core.py` / `rename_core.py` / `modes.py` / `preview.py` / `pathops.py` | 必須（共通コア・自然順・結合・リネーム・モード・プレビュー・共有フォルダー対策。どれか1つ欠いても起動しない） |
| `起動.bat` | 必須（ダブルクリック起動。Python を探し、`pypdf`/`openpyxl` が無ければ自動導入） |
| `README.md` / `LICENSE` / `LICENSE.ja.md` | 推奨（使い方とライセンス表示） |

受け取り用にまとめるスクリプトがあります（`dist\pdf-split-merge-rename\` と `dist\pdf-split-merge-rename-v<版>-min.zip` を生成。zip には `pdf-split-merge-rename/` フォルダー1個として12ファイルが入ります）。

```text
py -3 tools\make_dist.py
```

生成された zip の中身は12ファイルで破損なし（36 KB 前後。厳密なサイズとハッシュ値は `docs/PROJECT_DOCUMENT.md` 第6章に実測値として記録しています。README 自体が zip に入るため、ここに byte 数を書くと更新のたびにずれるため省略）。

受け取り側の要件は Windows と Python 3.10 以降だけで、`pypdf` と `openpyxl` は `起動.bat` が導入します。`dist/` は生成物なので git には入れません（`.gitignore` 済み）。
