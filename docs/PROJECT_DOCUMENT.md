## 0. 要求定義（依頼内容とそのままでの課題）

### 0.1 依頼文（ユーザー依頼そのまま）

> ①フォルダー内にあるPDFを結合して1つのPDFにしたい。
> ・ファイル名を昇順で結合していく。例: `001.pdf 008.pdf 003.pdf` がある場合、`001.pdf 003.pdf 008.pdf` の順で結合。
> ・フォルダーは参照ボタンで選べるように。
> ・結合後のPDFのファイル名は最初のPDFのファイル名をデフォルトとし、画面にて修正できるようにしたい。
>
> ②すでに分割されているPDFをリネームしたい。
> ・リネームのルールは「エクセルの固定セル名＋連番」と「固定セルから下の行のセルをファイル名とする」既存と同じ流れ。
> ・ファイルの連番やセルの順序は、ばらばらのPDFを昇順で並べた順序で割り当てる。
> ・フォルダーは参照ボタンで選べるように。
>
> 既存の pdf-split-unified へタブを2つ追加して、必要な項目を必要に応じて追加して完成させてください。
> GitHub のリポジトリおよび `E:\AI\Coding` 内のフォルダーは新規名称で作成してください。

### 0.2 現状の課題（なぜ必要か）

`pdf-split-unified` v1.0.0 は「1つのPDFをExcelの名前で1ページずつに分割する」ことだけができます。実務ではこの前後に次の作業が残ります。

| 場面の課題 | 現状（v1.0.0） | 追加するタブ |
| --- | --- | --- |
| スキャン機が出力した `scan001.pdf / scan003.pdf / scan010.pdf` を1通にまとめたい | 結合機能がない。別のソフトを探すか手作業 | **PDF結合** |
| 分割後に「連番がばらばら」「Excel の名前と対応していない」と気づいた | 分割し直し（Excel の名前を付け直す手段がない） | **Excelでリネーム** |
| Explorer の名前順だと `10.pdf` が `9.pdf` より前に来る | 該当機能なし | 両タブで**自然順**（数値部分の数値比較）を採用 |

### 0.3 受け入れ条件（依頼者が確認できること）

1. 1つのウィンドウにタブが4枚並び、タブを切り替えても既存の入力はそのまま残る。
2. 結合タブは「参照」でフォルダーを選ぶだけで、`001 / 003 / 008` の順に結合され、出力名は最初のPDF名が最初から入っていて書き換えられる。
3. リネームタブは、ばらばらな名前のPDFフォルダーに対して Excel の命名ルールで名前が変わり、**既存ファイルの上書きは起きない**。
4. 分割タブ2枚の挙動・エラー文言は v1.0.0 と同じ（既存ユーザーが混乱しない）。
5. 実行前に全件をプレビューでき、書き出し・名前変更を伴う操作はすべて事前検査で止まる。

## 1. 用語と決定事項

| 用語・決定 | 定義 |
| --- | --- |
| **自然順** | ファイル名を数字の連なりとそれ以外に分割し、数字は数値として、それ以外は大小を無視して比較する順序。`9.pdf` < `10.pdf`、`001 < 003 < 008`。同順位なら全文の大小無視、さらに同順位なら原文の文字コード順で決定的に揃える |
| **直下のみ** | 入力フォルダーの再帰走査はしない。フォルダー自体は対象に含めない |
| **PDF対象ファイル** | 拡張子が `.pdf`（大文字小文字無視）の通常ファイルのみ。隠し属性は対象に含めるが、一時フォルダー（`.pdf_split_*` / `.pdf_merge_*` / `.pdf_rename_*`）は除外 |
| **共通欄** | 全タブで共有する入力欄（PDF / 入力フォルダー / Excel / シート / 出力先）。タブごとに使う欄だけ検証する |
| **事前検査** | 書き出し・名前変更を開始する前に、全件を検査して1件でも不正なら一切の変更を行わず中止する規則 |

## 3. 機能定義（スクリプト毎の入出力・データ仕様）

### 3.1 `pdf_split_merge_rename.py`（GUI・エントリポイント）

- 共通欄5行（PDF / 入力フォルダー / Excel / シート / 出力先）＋タブ4枚＋プレビュー一覧欄＋状態欄・エラー欄。
- タブ内欄: タブ1 `セル番地` / タブ2 `開始セル` / タブ3 `結合後のファイル名` / タブ4 `ルールradio` + `適用先radio` + `セル番地`。
- `current_tab()` がタブID（`base_seq` / `per_cell` / `merge` / `rename`）を返し、`check_inputs(tab)` がタブごとに必要欄だけ検査する。
- プレビュー一覧の列構成をタブごとに切り替える（`_apply_columns(tab)`）。
- 実行ボタンはタブ内: 「分割を実行」×2 / 「結合を実行」/「リネームを実行」。
- タブ4の先頭説明は4行で、「このタブはPDFの分割を行いません（PDF 1件に1ファイル・ページ数はそのまま）／その場で改名: 入力フォルダー内で名前を変える／出力先へコピー: 共通欄の**出力先フォルダー**へ新しい名前で書き出す」を明示する。`適用先` radio（`inplace` / `copy`、既定 `inplace`）で切り替え、切り替えるとプレビューは「要更新」になる。`check_inputs` はタブ4の**コピーモードのときだけ**「出力先」を検査する（その場で改名では検査しない）。プレビューの要約は `プレビュー: PDF n 件 → n ファイル（分割なし・名前変更 x / 変更不要 y、名前変更は行っていません）`（コピーモードでは `コピー`）で、PDFの件数と出力ファイル数が同じであることを示す。完了メッセージは「変更 n 件 / 変更不要 m 件（PDFの分割は行っていません）/ フォルダー: <入力フォルダー>」または「コピー n 件 / 変更不要 m 件（PDFの分割は行っていません）/ 入力: ... / 出力: ...」（v2.0.2 で案内追記、v2.1.0 でコピーモード追加、v2.1.1 で分割しないことを明記）。

### 3.2 `split_core.py`（共通コア: 継承＋拡張）

- 既存の `parse_cell_address` / `read_cell_values` / `validate_filename_base` / `load_pdf` / `write_pages` / `split_pdf` は変更しない。

### 3.8 データ仕様（共通の安全規則）

- 一時名: リネーム `~pdf_rename_tmp_<n>.tmp` / 分割 `~pdf_split_*` / 結合 `~pdf_merge_*`。いずれも出力先・入力フォルダー内に作り、成功・失敗を問わず削除する。**`~` 始まりを先に使う**（`.` 始まりは Samba 既定の `hide dot files` などでエクスプローラーから隠れ、途中で止まったときに「PDFが消えた」と誤解されるため）。`~` 始まりを拒否する共有では `.` 始まり（`.pdf_split_*` / `.pdf_merge_*` / `.pdf_rename_tmp_<n>.tmp`）へ代替する（両方を `TEMP_NAME_PREFIXES` として入力対象・衝突検査から除外）。
- 書き出しは `open("xb")`（排他作成）。既存名への書き出し経路を持たない。書き出し後は `flush` → `os.fsync` で内容をサーバーへ届けてから閉じる（非対応の共有では fsync 失敗を無視して続行）。
- 名前変更は `pathops.move_into`（内部で `os.rename`）を使い、最終名が既存なら開始しない。一時的な共有違反（WinError 32 / 33 / 64）は 0.25/0.5/1/2 秒待って計5回まで再試行し、それでも失敗すれば「コピー（`open("xb")`）→ 元ファイル削除」で同じ結果にする。既存ファイルの上書きは行わない。
- 入力フォルダーの非PDFファイルは対象外だが、リネームの衝突検査には含める。

### 3.9 `pathops.py`（v2.0.1 で新規・ネットワークドライブ対策）

- 目的: SMB共有（NAS）はローカルフォルダーと同じに扱えないため、「名前を作る・動かす・消す」操作を1箇所に集めて、どの保存先でも同じ結果にする。
- 公開する関数: `is_unc` / `describe_os_error`（WinError 5 はアクセス権の案内、UNC は混雑の案内を添える）/ `make_staging_dir`（**`~` 始まりを先に作り**、拒否された場合のみ `.` 始まりへ代替）/ `tilde_prefix` / `temp_paths_for`（試作ファイルで実際に作れる一時名を選ぶ。`~` → `.` の順）/ `write_exclusive`（排他作成＋flush＋fsync）/ `copy_into`（v2.1.0 で追加。**宛先に既存があれば `FileExistsError`**、同一フォルダー内の `~pdf_rename_copy_*` 一時名で受け取ってから `move_into`、`finally` で残骸を掃除）/ `move_into`（**宛先に既存ファイルがあれば `os.rename` を呼ぶ前に `FileExistsError`**、その後に再試行→コピー代替）/ `remove_file` / `remove_tree`（削除の再試行）。
- `move_into` の既存宛先チェックは必須である: `os.rename` は POSIXでもWindowsでも既存ファイルがあると**無条件に上書き**するため、`open("xb")` 相当の排他性を名前移動でも担保する。
- 定数: `TEMP_NAME_PREFIXES`（`.` 始まりと `~` 始まりの両方）/ `COPY_TEMP_PREFIX = ".pdf_rename_copy_"`（v2.1.0。`temp_paths_for` が `~pdf_rename_copy_*` を先に使い、一覧からの除外も自動で効く）/ `RETRYABLE_WINERRORS = {32, 33, 64}` / `RETRY_DELAYS` / `CLEANUP_DELAYS`。
- `merge_core.TEMP_NAME_PREFIXES` は `pathops.TEMP_NAME_PREFIXES` を再exportしており、`is_temp_name` の互換は保つ。
- 名前変更は必ず `os.rename` を経由して呼ぶ（テストは `os.rename` を差し替えて失敗を再現する）。

## 5. 実行手順

### 5.2 結合タブの使い方

1. タブ「PDF結合」を選ぶ。
2. 「入力フォルダー」の参照ボタンでPDFが入ったフォルダーを選ぶ。

## 7. 既知の問題・留意点

- リネームは**同じフォルダー内のファイル名を変える**操作で、分割・結合より影響が大きい。そのため FR-R9 の2段階リネームとロールバックを必須とする。実行前にプレビューで新旧名を確認すること。
- リネームの取り消し（元名に戻すボタン）は今回含めない。失敗時の自動ロールバックのみ。
- 結合はPDFの構造（しおり・文書情報）は引き継がず、ページ内容の連結になる。しおりを維持した結合は対象外。
- 結合後のファイルが1000ページを超える場合も動作するが、メモリ上で PdfWriter がページを参照するため大きなPDFの結合は時間とかさが増える。
- 自然順は数字連なりを最大でも整数として扱う。桁数が極端に大きい数字連なりは文字列比較にフォールバックして順序の安定性を保つ。
- **ネットワークドライブ（NAS共有）** は入力・出力ともにそのまま指定できる（v2.0.1 / FR-C11）。ただし共有側の設定しだいで書き込めないことがあり、その場合は「アクセスが拒否されました。共有フォルダーが読み取り専用になっていないか、アクセス権を確認してください」を案内する。共有が一時的に混雑して名前変更が失敗するケースは再試行とコピー代替で吸収し、吸収できなかった場合のみ「保存先はネットワーク上の共有フォルダーです。共有が一時的に混雑している可能性があります」を添えて中止する（リネームは元の名前へ戻したうえで）。それでも保存できない場合は、表示されたエラー文言全体と保存先の共有パスをそのまま報告すること。
- 共有フォルダーでは `.` 始まりのファイル・フォルダーが見えないことがある（Samba 既定の `hide dot files` など）。v2.0.2 は一時名・一時フォルダーを `~pdf_split_*` / `~pdf_merge_*` / `~pdf_rename_tmp_*` で作り、`~` を拒否する共有でのみ `.` 始まりへ戻る（v2.1.0 のコピーは `~pdf_rename_copy_*`）。残骸を見つけたら上記の共有パスとともに報告する。
- **リネームタブの「適用先」は2択**（v2.1.0 / FR-R16）: 既定は「入力フォルダー内で名前を変える」で、このときはコピーを作らず共通欄の「出力先フォルダー」を使わない。もう1つは「出力先フォルダーへコピーして名前を変える」で、入力のPDFを動かさずに共通欄の出力先へ新しい名前で書き出す（このモードでは出力先が必須）。元の名前を残したい利用者・「名前を変えたらPDFが消えたように見えた」利用者はこちらを選ぶ。UIにも同じ案内を表示する。
- 「PDFが消えた」ように見える主な原因は、①共有サーバーが一時名を隠している、②名前変更が共有に反映されず残らなかった、の2つ。v2.0.2 は ①を `~` 始まりの一時名で避け、②を実行後の全件確認（FR-R15）でエラーとして表面化させる。どちらの場合も、フォルダーの表示更新と隠しファイル表示で中身を確認し、表示されたエラー文言をそのまま報告すること。
- **「Excelでリネーム」でPDFは分割されない**（v2.1.1 / FR-R19）。リネームタブは pypdf を読み込まない（`rename_core` はフォルダーの一覧とExcelの値だけで計画を作る）。そのため作られるファイル数は入力フォルダー直下のPDFの件数と必ず等しく、複数ページのPDFもページ数は変わらない。11ページのPDF1件ならプレビューは1行、11本のPDFなら11行である。リネーム後のファイル数がPDFの件数より多いと感じたら、①タイトル欄の版（v2.1.1 以降は表示される）を確認する、②プレビュー要約の `PDF n 件 → n ファイル（分割なし・...）` の n が一致しているかを見る、③入力フォルダーにすでにページ単位のPDFが入っていなかったか（結合タブや分割タブの実行で増えた可能性）を確認する。一致しない場合はプレビューのスクリーンショットと適用先・出力先パスを添えて報告すること。
