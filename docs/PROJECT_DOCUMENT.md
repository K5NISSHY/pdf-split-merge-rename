# PDF Split / Merge / Rename — プロジェクトドキュメント（v2.0.0）

- **プロジェクト名:** pdf-split-merge-rename
- **バージョン:** 2.0.0
- **製作者:** K5NISSHY
- **継承:** `pdf-split-unified` v1.0.0（GitHub: `K5NISSHY/pdf-split-unified`）の分割機能をそのまま引き継ぎ、**結合**と**リネーム**のタブを追加した新版。分割に関する要件・エラー文言・安全規則は元プロジェクトのものを一切変更しない。
- **参考コード:** `refs/PDF-Split-Rename/`、`refs/PDF-Split-Rename-By-Cell/`（読み取り専用。設計と日本語文言の由来）

## 0. 要求定義（依頼内容とそのままでの課題）

### 0.1 依頼文（ユーザー依頼そのまま）

> ①フォルダー内にあるPDFを結合して1つのPDFにしたい。
> ・ファイル名を昇順で結合していく。例: `001.pdf 008.pdf 003.pdf` がある場合、`001.pdf 003.pdf 008.pdf` の順で結合。
> ・フォルダーは参照ボタンで選べるように。
> ・結合後のPDFのファイル名は最初のPDFのファイル名をデフォルトとし、画面にて修正できるようにしたい。
>
> ②すでに分割されているPDFをリネームしたい。
> ・リネームのルールは「エクセルの固定セル名＋連番」と「固定セルから下の行のセルをファイル名とする」既存と同じ流れ。
> ・ファイルの連番やセルの順序は、ばらばらのPDFを昇順で並べた順序で割り当てる。
> ・フォルダーは参照ボタンで選べるように。
>
> 既存の pdf-split-unified へタブを2つ追加して、必要な項目を必要に応じて追加して完成させてください。
> GitHub のリポジトリおよび `E:\AI\Coding` 内のフォルダーは新規名称で作成してください。

### 0.2 現状の課題（なぜ必要か）

`pdf-split-unified` v1.0.0 は「1つのPDFをExcelの名前で1ページずつに分割する」ことだけができます。実務ではこの前後に次の作業が残ります。

| 場面の課題 | 現状（v1.0.0） | 追加するタブ |
| --- | --- | --- |
| スキャン機が出力した `scan001.pdf / scan003.pdf / scan010.pdf` を1通にまとめたい | 結合機能がない。別のソフトを探すか手作業 | **PDF結合** |
| 分割後に「連番がばらばら」「Excel の名前と対応していない」と気づいた | 分割し直し（Excel の名前を付け直す手段がない） | **Excelでリネーム** |
| Explorer の名前順だと `10.pdf` が `9.pdf` より前に来る | 該当機能なし | 両タブで**自然順**（数値部分の数値比較）を採用 |

### 0.3 受け入れ条件（依頼者が確認できること）

1. 1つのウィンドウにタブが4枚並び、タブを切り替えても既存の入力はそのまま残る。
2. 結合タブは「参照」でフォルダーを選ぶだけで、`001 / 003 / 008` の順に結合され、出力名は最初のPDF名が最初から入っていて書き換えられる。
3. リネームタブは、ばらばらな名前のPDFフォルダーに対して Excel の命名ルールで名前が変わり、**既存ファイルの上書きは起きない**。
4. 分割タブ2枚の挙動・エラー文言は v1.0.0 と同じ（既存ユーザーが混乱しない）。
5. 実行前に全件をプレビューでき、書き出し・名前変更を伴う操作はすべて事前検査で止まる。

## 1. 用語と決定事項

| 用語・決定 | 定義 |
| --- | --- |
| **自然順** | ファイル名を数字の連なりとそれ以外に分割し、数字は数値として、それ以外は大小を無視して比較する順序。`9.pdf` < `10.pdf`、`001 < 003 < 008`。同順位なら全文の大小無視、さらに同順位なら原文の文字コード順で決定的に揃える |
| **直下のみ** | 入力フォルダーの再帰走査はしない。フォルダー自体は対象に含めない |
| **PDF対象ファイル** | 拡張子が `.pdf`（大文字小文字無視）の通常ファイルのみ。隠し属性は対象に含めるが、一時フォルダー（`.pdf_split_*` / `.pdf_merge_*` / `.pdf_rename_*`）は除外 |
| **共通欄** | 全タブで共有する入力欄（PDF / 入力フォルダー / Excel / シート / 出力先）。タブごとに使う欄だけ検証する |
| **事前検査** | 書き出し・名前変更を開始する前に、全件を検査して1件でも不正なら一切の変更を行わず中止する規則 |

### 2.4 リネームタブ（FR-R: 新規）

| ID | 要件 |
| --- | --- |
| FR-R1 | 「入力フォルダー」の参照ボタンでフォルダーを選び、直下の `.pdf` を**自然順**に並べたものをリネーム対象とする |
| FR-R2 | 命名ルールをラジオボタンで選べる: **A: 固定セル値＋連番** / **B: 開始セルから下の行のセル値**。既存2モードと同じ生成関数（`modes.build_filenames`）を、ページ数の代わりに**ファイル数**で呼び出す |

| FR-R10 | 実行前に全件を検査し、1件でも不正なら名前変更を1つも実行しない |
| FR-R11 | プレビューは `順序 / 現在のファイル名 / 新しいファイル名 / 状態` を全件表示。名前変更は一切行わない |
| FR-R12 | 完了ダイアログに「変更 n 件 / 変更不要 m 件」とフォルダーを表示する |
| FR-R13 | Excel・PDFファイルの内容は一切変更しない（ファイル名のみを変更する） |

## 3. 機能定義（スクリプト毎の入出力・データ仕様）

### 3.1 `pdf_split_merge_rename.py`（GUI・エントリポイント）

- 共通欄5行（PDF / 入力フォルダー / Excel / シート / 出力先）＋タブ4枚＋プレビュー一覧欄＋状態欄・エラー欄。
- タブ内欄: タブ1 `セル番地` / タブ2 `開始セル` / タブ3 `結合後のファイル名` / タブ4 `ルールradio` + `セル番地`。
- `current_tab()` がタブID（`base_seq` / `per_cell` / `merge` / `rename`）を返し、`check_inputs(tab)` がタブごとに必要欄だけ検査する。
- プレビュー一覧の列構成をタブごとに切り替える（`_apply_columns(tab)`）。
- 実行ボタンはタブ内: 「分割を実行」×2 / 「結合を実行」/「リネームを実行」。

### 3.2 `split_core.py`（共通コア: 継承＋拡張）

- 既存の `parse_cell_address` / `read_cell_values` / `validate_filename_base` / `load_pdf` / `write_pages` / `split_pdf` は変更しない。
- 追加: `INVALID_FILENAME_CHARS` などの定数はそのまま使い、結合・リネームからも呼ぶ（ファイル名検証を1箇所に保つ）。

### 3.3 `modes.py`（ファイル名生成: 継承＋拡張）

- `BASE_SEQ` / `PER_CELL` の生成関数は変更しない。`page_count` 引数は「生成個数」の意味で、リネームではファイル数を渡して再利用する。
- 追加: リネームタブの radio 値をモードIDへ写す対応表（`RENAME_RULES`）。

### 3.4 `natural_sort.py`（新規）

- `natural_sort_key(name: str) -> tuple` を提供する。数字連なりは `(1, 数値, "")`、それ以外は `(0, 0, 小文字化テキスト)` のブロック列を作り、末尾に全文の casefold と原文を置いて決定的にする。
- `sort_pdf_names(names: Iterable[str]) -> list[str]` は `.pdf`（大小無視）だけを自然順で返す。
- 文字列以外の入力（None 等）は扱わない（呼び出し側でパス文字列を渡す）。

### 3.5 `merge_core.py`（新規）

| 関数 | 入力 | 出力・挙動 |
| --- | --- | --- |
| `list_merge_sources(folder: Path) -> list[Path]` | フォルダー | 直下の `.pdf` を自然順で返す。0件は `ValueError("PDFが見つかりません。...")`、1件は `ValueError("結合には2つ以上のPDFが必要です。")` |
| `default_output_name(sources: list[Path]) -> str` | 対象リスト | 最初のファイルの stem を返す（自然順の1番目） |
| `validate_output_name(name: str) -> str` | 結合後ファイル名 | `.pdf` を補い、`validate_filename_base` で検査して正規名を返す |
| `check_output_target(output_dir: Path, out_name: str, sources: list[Path]) -> None` | 出力先・出力名・入力 | 既存ファイルあり / 入力PDFと同名（大小無視）なら `FileExistsError` / `ValueError` |
| `build_merge_plan(folder: Path, out_name: str, output_dir: Path) -> MergePlan` | 入力 | 全PDFを開いて検査し、`MergePlan(sources, page_counts, total_pages, output_path)` を返す。読めないPDFは全件検査後に `ValueError`（先頭8件＋ほか N 件） |
| `merge_pdfs(plan: MergePlan) -> Path` | プラン | 一時フォルダー `.pdf_merge_*` に `xb` で書き、最終名へ移動。失敗時は削除してロールバック。戻り値は出力Path |

`MergePlan` は frozen dataclass（`sources: tuple[Path, ...]` / `page_counts: tuple[int, ...]` / `total_pages: int` / `output_path: Path`）。

### 3.6 `rename_core.py`（新規）

| 関数 | 入力 | 出力・挙動 |
| --- | --- | --- |
| `list_rename_targets(folder: Path) -> list[Path]` | フォルダー | 直下の `.pdf` を自然順で返す。0件は `ValueError` |
| `build_rename_plan(folder, excel, sheet, cell, mode) -> list[RenameItem]` | 入力 | 対象ファイル数で `modes.build_filenames` を呼び、新旧名を対応付ける。新名同士の重複は実行時 `ValueError`（プレビューは `abort_on_duplicates=False`） |
| `check_rename_plan(items, folder) -> None` | プラン | 対象以外の既存ファイルとの衝突を `FileExistsError`（先頭8件＋ほか N 件）で中止 |
| `apply_renames(items) -> RenameResult` | プラン | 2段階リネーム（FR-R9）。失敗時は元名へ戻す。`RenameResult(renamed: int, unchanged: int)` |

`RenameItem` は frozen dataclass（`order: int` / `source: Path` / `new_name: str` / `unchanged: bool`）。

### 3.7 `preview.py`（継承＋拡張）

- 既存 `PreviewRow`（分割用）は変更しない。
- 追加: `MergePreviewRow(order, filename, page_count, exists, unreadable)` と `RenamePreviewRow(order, old_name, new_name, unchanged, conflict, duplicate)`、および `display_cells()`。
- 追加: `build_merge_preview(...)` / `build_rename_preview(...)`（読み取りのみ。書き出し・名前変更なし）。
- `truncate_display` は行種別を問わず100件超をまとめる（既存を汎用化）。

### 3.8 データ仕様（共通の安全規則）

- 一時名: 分割 `.pdf_split_*` / 結合 `.pdf_merge_*` / リネーム `.pdf_rename_tmp_<n>.tmp`。いずれも出力先・入力フォルダー内に作り、成功・失敗を問わず削除する。
- 書き出しは `open("xb")`（排他作成）。既存名への書き出し経路を持たない。
- 名前変更は `os.rename` を使い、最終名が既存なら開始しない。
- 入力フォルダーの非PDFファイルは対象外だが、リネームの衝突検査には含める。

## 5. 実行手順

### 5.1 アプリの起動

`起動.bat` をダブルクリック。Python を探し（`py -3` → `python`）、`pypdf` / `openpyxl` が無ければ `pip install --user` を試みる。

### 5.2 結合タブの使い方

1. タブ「PDF結合」を選ぶ。
2. 「入力フォルダー」の参照ボタンでPDFが入ったフォルダーを選ぶ。
3. 「結合後のファイル名」に最初のPDF名が入っているので、必要なら書き換える。
4. 必要なら「出力先フォルダー」を変える（既定は入力フォルダー）。
5. 「プレビュー」で結合順序とページ数を確認 → 「結合を実行」。

### 5.3 リネームタブの使い方

1. タブ「Excelでリネーム」を選ぶ。
2. 「入力フォルダー」の参照ボタンでリネームしたいPDFフォルダーを選ぶ。
3. 「Excelファイル」「シート」を選び、ルールradio（固定セル値＋連番 / 開始セルから下の行）とセル番地を入れる。
4. 「プレビュー」で `現在のファイル名 → 新しいファイル名` と `[変更不要] / [衝突] / [重複]` を確認 → 「リネームを実行」。

## 7. 既知の問題・留意点

- リネームは**同じフォルダー内のファイル名を変える**操作で、分割・結合より影響が大きい。そのため FR-R9 の2段階リネームとロールバックを必須とする。実行前にプレビューで新旧名を確認すること。
- リネームの取り消し（元名に戻すボタン）は今回含めない。失敗時の自動ロールバックのみ。
- 結合はPDFの構造（しおり・文書情報）は引き継がず、ページ内容の連結になる。しおりを維持した結合は対象外。
- 結合後のファイルが1000ページを超える場合も動作するが、メモリ上で PdfWriter がページを参照するため大きなPDFの結合は時間とかさが増える。
- 自然順は数字連なりを最大でも整数として扱う。桁数が極端に大きい数字連なりは文字列比較にフォールバックして順序の安定性を保つ。
